How to read this report

Status is what the run did, not a verdict on the application. A Fail on a case badged known-defect is the expected outcome: those cases assert the behaviour the application should have and stay red until the finding is fixed.

Not run means the case exists in the suite but produced no result, normally because it was filtered out with -DexcludedGroups=creates-data, which keeps cases with real-world side effects - a registered account, a real SMS, a filed deposit, a withdrawal hold, a staked casino bet - out of an unattended run.

Evidence is the screenshot of the page as the case left it - captured for every case that ran, passed or failed, just before teardown closed the browser. A skipped case never ran, so it has none. Click an image for the full size.

Details, on every row, opens what would not fit in the table: the case as its source declares it, the diagnosis of a failure - exception, expected against actual, the element that could not be resolved, the lines of this project involved, and the full stack trace - and, for every row alike, the run's own record of what the browser did.

What the run did is that record. It is captured automatically while the case runs: NAV for a page load or a new tab, API for a call the site made of its own back end with the status it came back with, NETWORK for one that came back 4xx or 5xx, CONSOLE for a console or uncaught error, EVIDENCE for a screenshot, and STEP, CHECK and DATA for what the case itself narrated. A passing row carries one too, deliberately: a green result is a claim, and this is the working behind it.
